response caching for AI features

Green Caching — a third fewer calls to the model

Teams pay full price every time a model answers a question it has already answered. A response-caching layer intercepts the repeats: same output, a third fewer billed calls, and the saving compounds every day after the one it ships.

  • 30% fewer model calls and 17% lower latency across a 50-request benchmark
  • 100% output consistency — not one answer changed because it came from cache
  • Next: semantic caching so near-identical prompts hit too, with energy measured via CodeCarbon

3-person university study (SD-B-05). My role was the research and the paper — background, sustainability framing, references. The measurements above are the team's, not mine alone.

macOS app · for my own M.Sc. lectures

SmartNotes-AI — lectures in, study notes out

Press Record in the lecture hall and Stop at the end. The Mac transcribes the lecture on-device, Claude turns it into structured notes, and each lecture merges into one notebook per course — deadlines go straight into the calendar, and every line links to the second it was said.

  • On-device Whisper (WhisperKit, Core ML) — audio never leaves the laptop; crash-safe 5-minute chunks
  • Resumable five-step pipeline; Claude's output is schema-validated, then merged by deterministic, tested Swift — 327 automated checks
  • Deadlines de-duplicated across lectures and synced to the calendar; one-click read-only sharing on GitHub Pages

Designed and directed by me; built with Claude Code as a pair programmer — a written spec, a plan, test-first code and a review for every feature.
